# Android APDU laboratory

Минимальное Java-приложение для Pixel. Оно проверяет только синтетический цикл:

`Pixel IsoDep → NFC браслета → custom BLE GATT → обработчик Pixel → BLE → NFC → Pixel IsoDep`

APK 0.4 и native-модуль v6 установлены и проверены на Pixel 8a и p67glt / 3.201.026. Получен аппаратный PASS: SELECT и свежий challenge прошли полный NFC → BLE → Pixel → BLE → NFC путь; прогон занял 396,5 мс, после него подтверждены STOPPED и QUERY → STOPPED. Это один синтетический прогон, без Mir Pay и платёжных карт. Сохранены [журнал](../docs/evidence/pixel-v6-pass-log.txt) и [аппаратный отчёт с байтами и хешами сборок](../docs/evidence/pixel-gatt-v6-observation.json). Общая инструкция и ограничения — в [README проекта](../README.md).

## Сборка

Зависимости только локальные: Python 3, JDK, Android SDK platform 36 и build-tools 36.0.0. Gradle, Maven, сетевые загрузки и ADB в сборке не используются.

```sh
# Из корня проекта
python3 android/build.py
# Только JVM-проверки:
python3 android/build.py --test-only
```

Пути можно задать переменными `ANDROID_SDK_ROOT` (также `ANDROID_HOME`) и `JAVA_HOME`. Результат: `android/build/mbapdu-lab-debug.apk`; SHA-256 и разрешения — `android/build/build-result.json`. Сохранённый проверенный APK находится в [releases/apdu-lab-0.4.apk](../releases/apdu-lab-0.4.apk).

Ключ `.local/signing/lab-debug.keystore` — локальная отладочная подпись со стандартным паролем `android`; он исключён из Git и переносимого архива. При отсутствии ключа сборка создаёт новый. Для обновления уже установленного APK без смены подписи нужен прежний ключ. Повторные сборки APK в текущем окружении воспроизводятся побайтно; это не гарантия одинакового результата для разных версий инструментов.

Разрешения APK: `NFC`, `BLUETOOTH_SCAN` (`neverForLocation`), `BLUETOOTH_CONNECT`. Нет `INTERNET`, геолокации, аналитики, платёжных сервисов или доступа к Mir Pay. `minSdk=33`, `targetSdk=36`. Интерфейс на русском, без сторонних библиотек.

## Как выполняется тест

1. Пользователь выдаёт Bluetooth-разрешения и выбирает рекламируемый сервис. Можно явно ввести BLE-адрес. Поиск фильтруется по UUID прототипа **или** точному рекламному имени `MB-APDU`; журнал показывает имя и объявленные UUID только совпавших устройств. Кнопка «Диагностика · сопряжённый браслет» позволяет выбрать свой A234 из сопряжённых устройств с именем Xiaomi / Band 10 Pro и напрямую проверить GATT без поиска рекламы. Если сервис прототипа отсутствует, клиент выводит обнаруженные UUID только выбранного браслета и закрывает соединение без записи характеристик/CCCD.
2. GATT-клиент включает CCCD для TX. В APK 0.4 затем автоматически отправляется `QUERY` (`CONTROL 00`), который не меняет NFC. Кнопка NFC-теста остаётся недоступной, пока не получены **оба** подтверждения: завершённый ATT write и точный `STATUS STOPPED` с sequence этого QUERY. Журнал отдельно показывает запись и STATUS. Timeout проверки — 5 секунд; кнопку «Проверить BLE · без NFC» можно использовать для повторной проверки. `READY`, ошибка или другой статус требуют остановить NFC существующей кнопкой и подключиться снова. Переподключение сбрасывает подтверждение.
3. Только после проверки BLE кнопка теста отправляет `START_NFC`, расходуя подтверждение QUERY. Приложение показывает `STARTING:<phase>` и ждёт до 20 секунд. NFC ReaderMode включается только после точного `STATUS READY` с правильным sequence и подтверждения последнего ATT write команды START.
4. Пользователь прикладывает браслет к Pixel. Отдельный NFC-поток делает SELECT, затем challenge с 16 свежими байтами из `SecureRandom`.
5. Независимый Bluetooth HandlerThread принимает CAPDU, обрабатывает только синтетический whitelist и отправляет RAPDU. NFC-поток не блокирует этот обработчик.
6. PASS требует правильного NFC-ответа **и** ровно одного совпавшего challenge, действительно полученного в BT notification в текущем сеансе, **и** успешного `onCharacteristicWrite` для последнего фрагмента ответа. Самостоятельно вычисленный/отражённый NFC-ответ без BT-записи не считается успехом.
7. После одного теста приложение выключает ReaderMode и отправляет STOP. После успешного STOP при сохранённом соединении заново выполняется QUERY перед следующим тестом. Кнопка общей остановки ждёт `STOPPED`, затем закрывает GATT. Выход из foreground останавливает NFC; фоновой службы нет. Ошибка/timeout остановки явно отображается и закрывает Bluetooth, что должно запускать очистку в native-модуле.

В APK 0.4 отдельная кнопка «Возможности NFC · только чтение» отправляет `CONTROL 03` со свежим sequence и ждёт до 5 секунд. Результат подтверждается только после **обоих** событий: `INFO:<text>` с тем же sequence и завершённого ATT write. Ошибка, иной статус, пустой INFO, timeout или разрыв соединения не считаются подтверждением. Запрос не отправляется во время START, STOP или NFC-теста; он не запускает ReaderMode и не заменяет/сбрасывает подтверждение QUERY. Пока INFO выполняется, новый START недоступен. Страница прокручивается, поэтому кнопки и журнал доступны при малой высоте экрана и увеличенном шрифте.

## Контракт MB v1

Все многобайтные числа в кадре — big-endian. Заголовок 10 байт:

| Смещение | Поле |
| --- | --- |
| 0–1 | `4D 42` |
| 2 | версия `01` |
| 3 | тип |
| 4–7 | sequence uint32 |
| 8–9 | размер payload uint16 |
| 10… | payload |

| Тип | Направление | Payload |
| --- | --- | --- |
| 1 | браслет → Pixel | CAPDU, 1…261 байт |
| 2 | Pixel → браслет | RAPDU, 2…258 байт, тот же sequence |
| 3 | браслет → Pixel | STATUS UTF-8, 1…128 байт, sequence соответствующего CONTROL |
| 4 | Pixel → браслет | ровно 1 байт: `00` QUERY, `01` START_NFC, `02` STOP_NFC, `03` INFO (только чтение) |

Service: `7dbb0001-8e51-4f89-a9cb-9d40bb8c0e31`; RX write-with-response: `7dbb0002-8e51-4f89-a9cb-9d40bb8c0e31`; TX notify: `7dbb0003-8e51-4f89-a9cb-9d40bb8c0e31`; CCCD: `2902`.

Фрагменты передаются подряд, максимум 20 байт: работает с ATT MTU 23. Заголовок не повторяется на фрагментах. CRC отсутствует. Неправильный magic/version/type/length закрывает сеанс, без попытки угадать границу. Повтор request-sequence в одном соединении отвергается. Незавершённый входящий кадр и неподтверждённая ATT-запись имеют timeout 3 секунды. Parser, sequence history и proof сбрасываются при переподключении.

`STARTING:<phase>` — промежуточный статус запуска; финальный `READY` разрешает ReaderMode. `ERROR:<detail>` останавливает активный тест. `STOPPING:<phase>` — промежуточная очистка; `STOPPED` подтверждает её завершение.

## Синтетические APDU

- AID: `F04D424150445501` (**8 байт**).
- SELECT: `00A4040008F04D42415044550100`; ответ `9000`.
- Challenge: `8010000010` + 16 случайных байт + `00`.
- Ответ: challenge в обратном порядке, каждый байт XOR `A5`, затем `9000`.
- Любая другая CAPDU получает `6D00`; никакое другое приложение или SE не вызывается.
- Контрольный вектор: challenge `000102030405060708090A0B0C0D0E0F`, RAPDU `AAABA8A9AEAFACADA2A3A0A1A6A7A4A59000`.

`IsoDep` timeout — 4500 мс. Журнал допускает дополнительное ожидание до 600 мс для последнего Android ATT callback: NFC-ответ может уже прийти, пока этот callback ещё доставляется.

## Проверено и остаётся проверить

JVM-тесты проверяют wire-векторы, каждую границу фрагментации, поток из нескольких кадров, максимальные размеры, ATT20, whitelist, неверный Lc, ответ без BT, failed-write, повтор challenge, старый receipt, переподключение и независимое завершение записи. Дополнительно проверяются BLE preflight и независимый INFO: оба порядка STATUS/ATT, неверный sequence, READY/error, failed write и поздние callbacks после reset/timeout. INFO не может создать подтверждение QUERY. Сборка проверяет подпись APK, alignment и точный список разрешений.

На Pixel 8a и p67glt / 3.201.026 проверены INFO и один полный аппаратный прогон APK 0.4 с модулем v6: SELECT и свежий challenge прошли NFC → BLE → Pixel → BLE → NFC за 396,5 мс, затем подтверждены STOPPED и повторный QUERY → STOPPED. Это длительность всего прогона, а не отдельная задержка BLE. Длительные серии, сон и переподключение, независимый считыватель, другие прошивки и платёжный обмен ещё не проверены. Тест подтверждает наблюдаемый путь данных по собственному журналу, а не аппаратно заверенную идентичность браслета. Оставшиеся задачи перечислены в [roadmap](../docs/roadmap.md).

Первичные справочники Android: [ReaderMode](https://developer.android.com/reference/android/nfc/NfcAdapter#enableReaderMode(android.app.Activity,%20android.nfc.NfcAdapter.ReaderCallback,%20int,%20android.os.Bundle)), [Gatt writeCharacteristic](https://developer.android.com/reference/android/bluetooth/BluetoothGatt#writeCharacteristic(android.bluetooth.BluetoothGattCharacteristic,%20byte[],%20int)), [Bluetooth permissions](https://developer.android.com/develop/connectivity/bluetooth/bt-permissions).
