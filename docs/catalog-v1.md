# Каталог меток v1 и Roundabout RU NFC 3

Состояние на 14 ноября 2026 года: **каталог v1 и native UI1/UI2 уже запущены на браслете; исправленный UI3 проверен на компьютере и ожидает аппаратной проверки**. Целевая модель — `miwear.watch.p67glt`, прошивка **3.201.026**, телефон — Pixel 8a. Проверки адресов и ABI относятся только к этой прошивке.

На UI1 пользователь подтвердил первый запуск через нижний круг после перезагрузки, синхронизацию и выбор. Полученная фотография показывает карточку `NFC-Test` и состояние модуля **OK**. Журнал Pixel содержит `CATALOG_V1`, `CAT_COMMIT:12` и совпадающие `SELECT_OK`. [Наблюдение и статусы](evidence/tags/catalog-v1-observation.json). Это проверка загрузки, каталога и страницы; **NFC-readback версии с каталогом ещё не выполнялся**, сохранение каталога после следующей перезагрузки также требует отдельной проверки.

Следующая фотография UI2 подтвердила `NFC-Test`, **OK** и кнопку с иконкой загрузки. На ней также обнаружены тонкая рамка страницы, лишнее пространство снизу и квадратный фон NFC-круга на циферблате. UI3 исправляет эти видимые недостатки: сбрасывает стандартное оформление собственных native/Lua-контейнеров, убирает нижний текстовый блок и перераспределяет элементы по высоте. Для установки создан отдельный **Roundabout RU NFC 3** с новым ID `999999991`: Notify не заменил уже установленный ID `999999992`. Передача нового файла завершена, но результат исправления на браслете после перезагрузки пока не подтверждён.

Более ранняя связка APK 0.3 + Tag Bridge FACE v2 прошла один физический readback: 23 байта NDEF, 6 APDU, независимые BLE/ATT-подтверждения и STOPPED. [Отчёт](evidence/tags/pixel-0.3-v2-readback.json). Этот результат остаётся подтверждением базового моста, а не NFC-приёмкой нового каталога или UI3.

## Что добавлено

- Постоянный каталог на браслете: до **32 записей**, до **1024 байт NDEF** в каждой, стабильный UUID, ревизии каталога и записи, имя UTF-8 до 96 байт. Исходный UID хранится как справочная информация.
- Ручная синхронизация целого снимка с Pixel. Перед применением проверяются длины, число записей, уникальность ID, UTF-8, структура NDEF и SHA-256. Недописанный снимок не становится активным.
- Компактная native-страница **UI3**: карточка **256×128**, бейдж технологии, стрелки переключения и **«Обновить»**, выровненные по общим границам `x=40…296`. Ниже по центру группа **OK / FAIL** и кнопка **48×48** с Material-иконкой обновления для ручной загрузки core. Заголовка «NFC-метки», слова «Модуль», текстовой кнопки «Загрузить», UID, индекса «1 / N» и нижней строки сообщений на экране нет. Ширина карточки сохранена от первоначального квадрата 256×256, высота уменьшена вдвое.
- Отдельный циферблат **Roundabout RU NFC 3**, ID `999999991`: нижняя круглая кнопка вручную загружает модули после перезагрузки и открывает страницу. Другие кнопки, часы и штатная структура циферблата сохраняются. Подписи нижних показателей выровнены горизонтально; граница выбора NFC-круга приведена к его размеру 84×84.

Компоновка UI3 на экране 336×480 задаёт равные верхнее и нижнее поля по 32 пикселя:

| Элемент | Позиция `(x,y)` | Размер |
|---|---|---|
| Карточка | `(40,32)` | 256×128 |
| Предыдущая / следующая | `(40,204)` / `(176,204)` | по 120×56 |
| Обновить | `(40,304)` | 256×56 |
| OK / FAIL | `(105,400)` | 66×48 |
| Иконка загрузки | `(183,400)` | 48×48 |

Стандартные стили снимаются только с собственных native-корня и Lua-контейнера. Native-корню затем явно задаются чёрный фон и размер 336×480; системный PM-родитель не изменяется. У Lua-круга прозрачный фон в обычном состоянии, круглый фон используется только для статуса загрузки. Эти изменения не затрагивают core или NFC.

Поддерживаемая эмуляция — **содержимое NDEF как NFC Type 4 через Pixel**. Каталог может хранить сведения о других метках, но не переносит их аппаратный UID, секреты, защищённые секторы или права доступа. Mir Pay не подключён. Считывание каталога и выбор возможны без BLE после загрузки модуля; для NFC-обмена всё ещё нужны подключённый Pixel и открытое приложение.

## Ручной сценарий

1. После перехода со старого прототипа перезагрузить браслет: старые и новые резидентные модули нельзя загружать одновременно. Выбрать Roundabout RU NFC 3, разбудить экран и нажать нижний NFC-круг. Просто открытие циферблата ничего не загружает.
2. Первый тап извлекает встроенные файлы и запускает core/UI. Следующие тапы используют штатное открытие зарегистрированной native-страницы. Проверка регистрации в bootstrap ограничена тремя секундами. `REBOOT` означает, что повторная небезопасная загрузка заблокирована; это не команда автоматической перезагрузки.
3. В приложении Pixel создать текст/ссылку либо считать доступную NDEF-метку, подключиться по Bluetooth и **вручную синхронизировать каталог**. Приложение сначала проверяет возможность `CATALOG_V1`; старый core не считается совместимым только по UUID Bluetooth-сервиса.
4. На браслете нажать **«Обновить»**, затем выбрать запись стрелками. Переходы не зациклены. При пустом каталоге показывается «Нет меток». Изменение выбора сначала останавливает текущий NFC-сеанс и дожидается очистки маршрута.
5. Для обмена Pixel подтверждает точные ID, ревизии и хеш выбранной записи. **NFC запускается только отдельной ручной командой на Pixel** после этого подтверждения. Тап по кругу, загрузка модуля, синхронизация, выбор записи и повторное соединение NFC не запускают.
6. После использования выполнить STOP и дождаться STOPPED. Возврат со страницы браслета сам по себе не обещает STOP. Сохраняются пределы 120 секунд на сеанс и 3 секунды на ответ APDU; уход Android-приложения с переднего плана завершает его сеанс и соединение.

Маленькая **кнопка с иконкой обновления рядом с OK / FAIL** сохраняет функцию прежней «Загрузить»: вручную пытается запустить отсутствующий core из уже извлечённого файла. Большая **«Обновить»** выше только перечитывает состояние страницы. Кнопка загрузки сначала проверяет native-провайдер и защиту от повторной загрузки. Уже загруженный, но неработающий модуль требует перезагрузки; принудительная выгрузка резидентного кода не выполняется. Причины отказа и служебные сообщения записываются в `/tmp/nfc_tags_ui_notice`, без отдельного текстового блока на странице. Успешный `insmod` или файл-маркер не равен работоспособности: **OK** требует корректного API, свежего heartbeat и отсутствия ошибки core. Это состояние модуля, **не подтверждение готовности NFC или соединения с Pixel**.

Страница выполняет одно обновление при открытии и по кнопке. После выбора или ручной загрузки она проверяет изменение состояния каждые 500 мс **не более 20 секунд**; новый ручной выбор перезапускает это ограниченное окно. При закрытии страницы UI-таймеры удаляются. Бесконечного опроса страницы, удержания экрана и реализации RF-пробуждения нет. Существующий control-loop core остаётся отдельной частью моста; его работу при сне или смене приложений ещё нужно проверить на устройстве.

## Хранение и согласование

Каталог хранится в `/data/tag_catalog/catalog.bin`, выбранная запись — в `selected.bin`. Временные `catalog.next` и `selected.next` не загружаются после перезапуска. Полная запись и закрытие файла проверяются, снимок перечитывается и проверяется перед `rename`. В памяти активный каталог заменяется только после успешного сохранения. При обрыве обновления связанных файлов несовпадающий выбор отклоняется, а не привязывается к другой записи. Атомарная замена проверена на уровне модели файловых операций; **сохранность при внезапном отключении питания на реальной файловой системе пока не доказана**, `fsync` не предполагается.

Снимок при максимальных длинах полей занимает 38 924 байта; общий предел протокола — 65 536 байт. Передача идёт последовательными BEGIN/DATA/COMMIT, порциями до 240 байт, только при остановленном NFC. Ожидание очередной части ограничено 15 секундами. Ревизия с другим содержимым не может перезаписать уже применённую равную или более новую ревизию.

Выбор передаётся отдельным запросом с UUID, ревизиями и SHA-256 NDEF. ACK привязан к запросу и текущему BLE-соединению; устаревший ответ не разрешает START. На согласование отведено 30 секунд. При переподключении браслет повторно предлагает свой сохранённый выбор; Pixel не подменяет его прежней локальной записью автоматически.

Native UI получает каталог через проверенный системный реестр: собственный provider `0xD6`, `dev.mbapdu.catalog.api.v1`. Проверяются имя, метка и версия ABI; указатели из файлов не исполняются. Страница использует собственный ID `0xD4`, как прежний NFC-экран, поэтому при занятом ID регистрация завершается отказом. Встроенные приложения не заменяются.

Точные форматы, ограничения и ABI: [протокол](../tags/catalog/PROTOCOL.md), [native core](../tags/catalog/README.md), [api.h](../tags/catalog/api.h), [bootstrap](../tags/bootstrap/README.md). Режим питания и отложенная опция пробуждения описаны в [ТЗ](technical-spec.md).

## Сборка и воспроизводимость

Из корня проекта:

```sh
python3 tags/catalog/test.py
python3 tags/catalog/build.py
python3 tags/launcher/test_catalog_ui.py
python3 tags/launcher/build_catalog_ui.py
```

Упаковщик использует Python с Pillow; bootstrap-тесты дополнительно требуют `lupa.lua54`. В текущем рабочем окружении:

```sh
build/shortcut-research-venv/bin/python tags/bootstrap/test.py
build/shortcut-research-venv/bin/python tags/bootstrap/build_face.py \
  --core tags/catalog/build/catalog_core_v1.elf \
  --ui tags/launcher/build/nfc_tags_catalog_ui_v3.elf \
  --extra left.bin=tags/launcher/icons/left.bin \
  --extra right.bin=tags/launcher/icons/right.bin \
  --extra refresh.bin=tags/launcher/icons/refresh.bin
build/shortcut-research-venv/bin/python tags/roundabout/level_labels.py \
  --input build/roundabout-ru-nfc3.face \
  --output build/roundabout-ru-nfc3-final.face \
  --preview build/roundabout-ru-nfc3-final.png
build/shortcut-research-venv/bin/python tags/roundabout/check_clearance.py \
  --face build/roundabout-ru-nfc3-final.face
build/shortcut-research-venv/bin/python tags/bootstrap/verify_final.py
```

Генерируемые кандидаты: `tags/catalog/build/catalog_core_v1.elf`, `tags/launcher/build/nfc_tags_catalog_ui_v3.elf`, `build/roundabout-ru-nfc3-final.face`. UI3 использует имя модуля `NFC_Tags_Catalog_UI_V3`, ресурс `app/lua/catalog_ui_v3.elf` и путь `/data/tag_catalog/ui-catalog-v3.elf`. Загрузчик проверяет attempted-защиты UI1/UI2/UI3 и требует перезагрузки при старых loaded/READY-маркерах или частичной загрузке прежнего UI; точное значение нового маркера — `catalog_ui_v3\n`. Core v1 не меняется. Замороженные прежние версии сохраняются. UI3 — **10 784 байта**, SHA-256 `721431bcd5e662a1722ef363d4dd0aef3d2ce9e330bf36368a8da02b2126b72d`; core — **37 840 байт**, SHA-256 `f3d3fde87de70310adccfb318ef06092f7523635c993752521f56f956a5e17f1`. Упаковщик сохраняет ELF целиком в FileResource; ограничение старого слота Recorder 31 272 байта здесь не используется.

Последний проход выравнивает только 80 нижних текстовых подписей. **Числовые показатели, их наклон, координаты и данные сохранены как в исходном циферблате.** «Ккал» и «ЧСС» справа сдвинуты на 12 пикселей вправо, их Y сохранён. Проверка всех кадров прогресс-бара во всех восьми темах подтверждает минимум три пустых пикселя до «Ккал» и два до «ЧСС»; иконки не изменены. Отчёты: `tags/bootstrap/validation.json`, `tags/bootstrap/final_validation.json`, `tags/roundabout/level_labels_validation.json`, `tags/roundabout/label_clearance_validation.json`. Галерея пересобрана только в области изменённых подписей; исходные пиксели чисел сохранены. Это офлайн-превью ресурсов, а не снимок экрана браслета.

`tools/package_bundle.py` включает исходники каталога, bootstrap, UI-иконки, Android-ресурсы и тесты на устройстве. Каталоги `releases/catalog` и резервный `releases/catalog-ui1` включаются **только при наличии полного набора с manifest.json и SHA256SUMS, проходящего проверку**. Для прежних Android UI-релизов поддерживается их схема с одним APK; архив сохраняет их README и проверяет контрольные суммы. Локальные build-каталоги, ключи подписи и пользовательские метки не включаются.

## Проверки и следующий этап

На компьютере пройдены три ASAN/UBSAN-набора core, **379 проверок native UI3**, **20 Lua-тестов bootstrap** и проверки Android-протокола. Проверяются максимальный каталог, повреждённые/усечённые сообщения, ошибки записи/закрытия/rename, пересогласование выбора, остановка перед переключением, тайм-ауты, повторная загрузка и жизненный цикл страницы. UI3 проверен на границы элементов, расположение карточки 256×128, стрелок и кнопок, сброс оформления собственного корня и отсутствие нижней строки; фактический рендер остаётся аппаратной проверкой. Упаковщик сверяет firmware, ELF, каждый встроенный файл и допустимые изменения ресурсов. Прежние core v2 и APDU Lab остаются отдельной регрессионной базой.

Для принятия **UI3 и полной связки с каталогом** ещё нужно:

1. После обязательной перезагрузки при переходе с UI1/UI2 повторить первый тап и открытие **UI3**, последующие тапы, обе соседние кнопки циферблата и штатный жест возврата. Предыдущие страницы уже наблюдались на устройстве; это не снимает проверку UI3 и его загрузчика.
2. Проверить фактическую компоновку UI3 на экране 336×480: отсутствие тонкой рамки, равные поля по 32 пикселя, карточку 256×128, общие границы навигации и «Обновить», кнопку загрузки 48×48, русский шрифт, длинные имена, бейджи, пустой каталог и отсутствие наложений. На циферблате проверить отсутствие квадратного фона NFC-круга, все четыре темы, AOD и рамку редактирования.
3. Передать несколько записей и предельный каталог, выбрать записи на браслете, проверить согласование с Pixel, переподключение и сохранение после перезагрузки. Отдельно проверить обрыв передачи и сохранение прежнего каталога.
4. Для разных выбранных NDEF выполнить физический readback с точным совпадением содержимого, независимыми BLE/ATT-событиями и STOPPED после очистки. Проверить смену выбора во время сеанса и отказ запуска метаданных без NDEF.
5. Подтвердить живой heartbeat при переходах между циферблатом и native-страницей. Сон, фоновая работа, расход батареи и RF-пробуждение остаются отдельными задачами; текущий этап их не реализует.

Результаты устройства следует хранить отдельно от host-проверок. Наблюдавшийся успех UI1/UI2 и синхронизации не означает приёмку UI3 или NFC-readback каталога; успешная сборка и упаковка тоже не заменяют эти проверки.
