# MIFARE Classic — статические свидетельства

Сгенерировано [tools/inspect_classic_firmware.py](../../../tools/inspect_classic_firmware.py)
по образу `references/vela_ap.bin` (SHA-256
`66701c11073aebbd1d925cb6e097aa56a3101fc747d9f0fc280cd250dce72a40`).

Это **только статический анализ**: команды на браслет не отправлялись,
конфигурация NFC/eSE и flash не изменялись, физическая эмуляция и домофон
не проверялись.

## Файлы

| Файл | Содержимое |
| --- | --- |
| [manifest.json](manifest.json) | хеш образа, параметры конфигурации, проверки адресов, ограничения |
| [nfc-a-config.json](nfc-a-config.json) | разобранный `CORE_SET_CONFIG`: `0x30..0x33`, все параметры и усечённый `0xA0` |
| [addresses.json](addresses.json) | 17 проверенных смещений и первые байты кода |

## Что подтверждено

- SHA-256 образа совпадает с сохранённым.
- По смещению `0x95c294` находится шаблон `CORE_SET_CONFIG` с 16
  заявленными параметрами.
- `0x30 = 08`, `0x31 = 03`, `0x32 = 20`, `0x33 = 01 02 03 04`.
- 17 байтовых префиксов по адресам совпадают с записанными.

## Что не доказано

- Что контроллер принимает новый NFCID1.
- Что в эфире появляется заданный UID.
- Что существует доступный Classic-апплет в eSE и путь его персонализации.
- Что конкретный домофон принимает браслет.
- Что полная Classic-эмуляция возможна.

## Аномалия

Последний параметр `0xA0` заявляет длину 29 байт, но в статическом шаблоне
после него остаётся только 3 байта. Скрипт фиксирует это как
`truncated_param` и не считает шаблон полным `CORE_SET_CONFIG`.
