Exact p67glt / 3.201.026 monotonic clock binding

Firmware SHA256:
66701c11073aebbd1d925cb6e097aa56a3101fc747d9f0fc280cd250dce72a40

clock_gettime: code 0x2c1c8e70, Thumb pointer 0x2c1c8e71.
Discovery: supplied recorder ELF .text+0x1128 (now_ms) calls this pointer with
clock id 0 and a 16-byte temporary. Recorder's helper uses only seconds;
we did NOT reuse that coarse or realtime helper.

Independent disassembly:
0x2c1c8e7e compares clock ID with 1; 0x2c1c8e82 branches to 0x2c1c8ea0.
ID4 takes the same branch. That path passes output pointer to 0x2c1c9024.
ID0 takes a different path and adds the global wall-clock base at 0x200bf538.
This is the expected CLOCK_MONOTONIC=1 / CLOCK_BOOTTIME=4 vs CLOCK_REALTIME=0
dispatch, consistent with OpenVela/NuttX source listed below.

0x2c1c9024 obtains elapsed ticks from 0x2c17d2d0, converts them to a timespec,
stores seconds low32 at output+0 (0x2c1c908c), seconds high32 at output+4
(0x2c1c9072), and nanoseconds32 at output+8 (0x2c1c908e).
This independently verifies the 64-bit seconds / 32-bit nanoseconds layout.
The caller allocates 16 bytes, preserving ARM 8-byte alignment.
The conversion includes a 100000 ns factor (literal 0x186a0); our code does
not depend on the tick frequency and uses the returned nanoseconds directly.

native_clock.c verifies first 24 bytes of BOTH functions before calling them.
It returns uint32 milliseconds modulo 2^32, suitable for unsigned elapsed
differences over a 3-second timeout. Any ABI fingerprint/range/error failure
returns -1; the caller must fail closed, not advance a synthetic UI counter.
