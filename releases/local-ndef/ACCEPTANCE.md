# Приёмка локального NDEF Type 4 (без Pixel в момент чтения)

Кандидат для ручной проверки. **Аппаратно не проверялся.** Реализация и host-тесты
относятся только к `miwear.watch.p67glt`, прошивка **3.201.026**.

## Артефакт

| Поле | Значение |
| --- | --- |
| Файл | `build/roundabout-ru-nfc-local.face` (в релизной папке — `releases/local-ndef/roundabout-ru-nfc-local-p67glt.face`) |
| Циферблат | **Roundabout RU NFC Local** |
| Face ID | `999999969` |
| Размер | `3 630 843` байт |
| SHA-256 | `04308934c394cdff7526636b749eb325878375f3fad6dad88351f1b22a2a9905` |
| Core | `Tag_Catalog_Local_V2`, SHA-256 `3523a25685d232a0cc7ca7585bda881a5e7db32b405f2417a25afd912a347e88` |
| UI | `NFC_Tags_Catalog_UI_V5`, SHA-256 `8bcb144ca60223a7f5da357dbe5987c4465d6020e8dbafaeaf08d71c184aa95c` |
| Lua | `main_local.lua`, SHA-256 `475720273799ff2ec32f3da03645953c69c113aa87c31559fdafa794ffdb1a2b` |

Face ID новый, поэтому Notify должен установить его отдельной записью, не заменяя
предыдущий циферблат. Имя и ID можно проверить в списке циферблатов.

## Что именно проверяем

1. Браслет **сам** отвечает на NFC Forum Type 4 NDEF, когда Pixel отключён/выключен.
2. Сеанс стартует только при открытии страницы «NFC-метки» и заканчивается по
   тайм-ауту/уходу со страницы.
3. NFC-маршрут очищается, штатный NFC не ломается.
4. Каталог и выбранная запись переживают перезагрузку.
5. Ошибки не выглядят как успешное чтение.

Платёж, UID, eSE, транспорт и RF-пробуждение в этот кандидат **не входят**.

## Подготовка

- Браслет: точная модель `miwear.watch.p67glt`, прошивка `3.201.026`.
- Телефон для установки: Notify for Xiaomi (текущий способ установки `.face`).
- Телефон для синхронизации: Pixel 8a с APK **Tag Bridge 0.4.1** (существующий APK,
  новый APK не требуется).
- Второй NFC-считыватель: другой Android/iPhone с NFC Tools / NFC Reader, либо
  аппаратный NDEF-считыватель. Для чистоты опыта на нём не должно быть запущено
  приложение, которое само является эмулятором.
- Заряженный браслет; экран включён; яркость достаточная.
- Штатный NFC на браслете включён. Если NFC выключен в настройках, локальный
  старт вернёт ошибку, а не `NFC`.

## Установка

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| I1 | Передать `.face` через Notify и выбрать **Roundabout RU NFC Local** | Циферблат появился отдельно; старый циферблат не заменён |
| I2 | Перезагрузить браслет | После загрузки доступны нижний круг и меню приложений |
| I3 | Один раз нажать нижний круг | Идёт загрузка/перезагрузка; после неё в меню появляются **NFC-метки**, **Mi Home**, **Модули** |
| I4 | Открыть **NFC-метки** | Страница «Пульт»; карточка выбранной записи или «Нет меток»; статус модуля OK |

Если после первого нажатия появилась ошибка, не повторять загрузку вслепую:
перезагрузить браслет и проверить `/tmp/tag_bootstrap_diagnostic` (если доступен
способ чтения `/tmp`). Повторная загрузка резидентного модуля запрещена.

## Синхронизация

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| S1 | В Pixel создать текстовую запись, например `LOCAL-NDEF-TEST` / `Hello-from-Band` | Запись видна в Tag Bridge |
| S2 | Синхронизировать каталог с браслетом (страница **NFC-метки** на браслете должна быть закрыта) | На Pixel `CAT_COMMIT`, на браслете запись доступна |
| S3 | На браслете открыть **NFC-метки** и выбрать запись стрелками | Карточка показывает имя; бейдж `NDEF` |
| S4 | Закрыть приложение Pixel; выключить Bluetooth на Pixel (или выключить Pixel) | Связи с браслетом нет |
| S5 | Снова открыть **NFC-метки** на браслете | В течение ~0,5–2 с бейдж меняется на `NFC…`, затем `NFC` |

Важно: синхронизация и выбор записи могут выполняться с телефоном; для самого
чтения телефон уже не нужен. При открытой странице локальный NFC уже активен,
поэтому транзакция каталога отклоняется — синхронизируйте при закрытой странице.

## Основной опыт: чтение без Pixel

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| N1 | Открыть на втором телефоне NFC Tools / NFC Reader | Режим чтения включён |
| N2 | Приложить браслет к NFC-антенне второго телефона (экран браслета включён, страница «NFC-метки» открыта) | Считыватель видит NDEF Type 4 |
| N3 | Прочитать сообщение | Текст совпадает с `LOCAL-NDEF-TEST` / `Hello-from-Band` побайтно |
| N4 | Повторить N2–N3 **20 раз** (при необходимости закрывать/открывать страницу или нажимать «ОБНОВИТЬ»; сеанс — 60 с) | 20 успешных чтений; без зависаний и ложных `NFC` |
| N5 | Оставить страницу открытой и подождать 60 с | Бейдж возвращается к `NDEF`; чтение больше не отвечает |
| N6 | Снова открыть страницу и прочитать | Чтение снова работает |
| N7 | Уйти со страницы (штатный возврат) | Сеанс остановлен; повторное открытие снова включает NFC |

Если при чтении второго телефона на браслете остаётся `NFC…` и чтения нет —
зафиксировать время, модель считывателя и состояние экрана; это не PASS.

## Маршрут и совместимость

| # | Действие | Ожидаемый результат |
| --- | --- | --- |
| R1 | После N7 проверить штатный NFC браслета (кошелёк/другая карта, если настроена) | Штатный сценарий не сломан; нет «залипшего» маршрута |
| R2 | Перезагрузить браслет | Каталог, выбранная запись и приложение восстанавливаются |
| R3 | Повторить одно чтение без Pixel | PASS |
| R4 | Проверить, что после перезагрузки не требуется заново устанавливать `.face` | Автозагрузка сработала; приложения в меню |

## Границы и негативные проверки

| # | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| E1 | Каталог пуст | «Нет меток»; NFC не стартует; нет ложного `NFC` |
| E2 | Выбрана запись без NDEF (метаданные) | Бейдж «Сведения»; NFC не стартует |
| E3 | На браслете нет выбранной записи | «Выберите метку»; NFC не стартует |
| E4 | Во время сеанса выбрать другую запись | Старый сеанс останавливается; после выбора новый стартует; читается новое содержимое |
| E5 | Запись NDEF около 1024 байт | Полное содержимое читается; нет обрыва на границе 256 байт |
| E6 | Телефон Pixel с включённым Bluetooth, но без приложения | Чтение всё равно работает: BLE не обязателен |
| E7 | Экран браслета погас/страница закрыта | Сеанс не остаётся активным; после возврата работает заново |

## Что считается PASS

- N3/N4: не менее 20 из 20 успешных чтений с точным содержимым при выключенном
  Pixel/Bluetooth.
- N5: сеанс действительно завершается по 60-секундному тайм-ауту.
- R1/R2/R4: штатный NFC не сломан, данные и выбор пережили перезагрузку.
- E1–E3: нет ложного запуска NFC без NDEF.
- Ошибки не маскируются: при неудаче на экране нет `NFC`, а в логах есть причина.

## Что приложить к отчёту

1. Модель и прошивка браслета, модель второго считывателя.
2. Результат по каждому пункту: PASS/FAIL и краткое наблюдение.
3. Фото экрана браслета в состояниях `NDEF`, `NFC…`, `NFC`, а также ошибки (если была).
4. Скриншот/текст, который прочитал второй телефон (для N3 и E5).
5. Если доступны файлы `/tmp`:
   - `/tmp/nfc_tags_catalog_ui_ready` — ожидается `catalog_ui_v5`;
   - `/tmp/tag_catalog_local_loaded` — ожидается `catalog_v2_local`;
   - `/tmp/nfc_tags_ui_state` — ожидается `NFC_CATALOG_UI5 ... READY`;
   - `/tmp/tag_catalog_local_diag` — последняя стадия core (например,
     `LOCAL_NDEF_LOADED` или `LOCAL_TRANSPORT`);
   - `/tmp/tag_bootstrap_diagnostic` — только если установка/загрузка не удалась.
6. Время и последовательность действий для любого FAIL.

## Известные ограничения кандидата

- Сеанс запускается **открытием страницы**, а не RF-полем; «просто поднести» без
  открытия приложения пока нет.
- Сеанс ограничен **60 секундами**; после тайм-аута нужно открыть страницу заново
  или нажать «ОБНОВИТЬ».
- NDEF-содержимое публично: любой считыватель увидит его, пока сеанс активен.
- Нет UID/eSE/платежей/транспорта; это по-прежнему отдельные внешние зависимости.
- Только точная модель/прошивка; обновление прошивки требует новой сборки.
- Автозагрузка зависит от установленного циферблата; смена циферблата может
  остановить автозагрузку.
- Аппаратная приёмка этим документом не подтверждена; все пункты выше — ожидаемое
  поведение.

## Откат

Выбрать прежний циферблат и перезагрузить браслет; резидентный модуль живёт до
перезагрузки. Установка нового `.face` не меняет прошивку и штатный кошелёк.
