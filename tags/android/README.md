# Метки · NFC — Pixel

Отдельное приложение `dev.mbapdu.tags` для каталога меток и выбранной записи на браслете. Оно не заменяет APDU Lab и не обращается к Mir Pay.

В версии **0.3** при отсутствии сервиса Tag Bridge `0011` и наличии старого APDU Lab `0001` допускается одна попытка `BluetoothGatt.refresh()`. Возвращённое `true` означает принятие запроса, а не завершённое обновление кэша. Приложение сохраняет GATT-соединение, ждёт автоматического обнаружения и через три секунды при необходимости запускает одно явное discovery. После повторного отсутствия сервиса или timeout соединение закрывается без записи характеристик. Автоматический и явный callback не могут вызвать повторную настройку CCCD. Unpair и обход hidden-API policy не используются. На Pixel этот путь позволил обнаружить новый сервис и завершить подключение.

## Возможности версии 0.3

- Считать доступный UID, список NFC-технологий, ATQA/SAK и параметры ISO-DEP. Данные метки не изменяются; аутентификация, подбор ключей и чтение защищённых секторов не выполняются.
- Сохранить NDEF-сообщение до 1024 байт или создать текст/ссылку. Каталог до 32 записей хранится в закрытом файле приложения; есть выбор, переименование и удаление.
- Передать выбранные имя, UID и технологию по BLE на отдельный циферблат **Tag Bridge**. На браслет отправляется ASCII-транслитерация имени; оригинальное имя остаётся на Pixel. Пока на браслете отображается одна выбранная запись, а полный список доступен на телефоне.
- Эмулировать **содержимое NDEF как NFC Type 4**, отвечая на APDU с телефона через BLE. UID, аппаратный тип исходной метки, ключи и права пропуска не переносятся. Для записей без доступного NDEF кнопка эмуляции отключена.

Принят ручной режим: пользователь будит браслет перед использованием; приложение и циферблат должны оставаться открытыми. Постоянная фоновая работа браслета не планируется. Сеанс ограничен двумя минутами; ответ на отдельную APDU ожидается до трёх секунд. После ухода приложения с переднего плана оно запрашивает STOP и закрывает Bluetooth. Подтверждение ATT-записи не считается подтверждением очистки NFC: требуется STATUS STOPPED. Будущая опция пробуждения по полю описана только в [ТЗ](../../docs/technical-spec.md), без реализации.

## Проверка на одном Pixel

После подключения, передачи выбранной метки и получения READY нажать **«Проверить браслет этим Pixel»**, затем приложить браслет к NFC-антенне Pixel. В этом диагностическом режиме Pixel одновременно работает физическим NFC-считывателем и независимым BLE-обработчиком:

`Pixel IsoDep → NFC браслета → BLE → обработчик Pixel → BLE → NFC браслета → Pixel IsoDep`.

Считыватель выполняет SELECT приложения, читает CC, выбирает NDEF-файл и читает NLEN/содержимое. PASS требует совпадения содержимого с выбранной меткой, каждой пары CAPDU/RAPDU с независимым BLE-журналом и завершённых ATT-записей. Затем проверяются STOPPED и повторный QUERY. Итог проверки отображается отдельно от состояния Bluetooth. В обычном режиме эмуляции ReaderMode на Pixel выключен.

**13 ноября 2026 года APK 0.3 + FACE v2 прошли один полный аппаратный readback.** Созданная в приложении запись `NFC-Test` с текстом `Hello-from-Pixel` (**23 байта NDEF**) совпала после чтения с браслета; проверены **6 APDU**, независимые BLE-события и подтверждения ATT-записей. Затем получены `STOPPED` и повторный `QUERY → STOPPED`. Пользователь подтвердил имя, `NDEF` и `SELECTED` на экране браслета. Финальный STOP и отключение Bluetooth также подтверждены. [Отчёт](../../docs/evidence/tags/pixel-0.3-v2-readback.json) · [Журнал](../../docs/evidence/tags/pixel-0.3-v2-readback-log.txt) · [Проверенный APK](../../releases/tags/tag-bridge-0.3.apk).

Первая попытка завершилась `NFC transmit failed`, её причина неизвестна. При такой ошибке текущий интерфейс может заменить подробную ошибку считывателя общим сообщением о завершении NFC-сеанса; это задача дальнейшей диагностики. Создание, сохранение и сохранность записи после обновления APK проверены; чтение настоящей физической метки, работа после сна и в фоне ещё не проверены. [Общий статус и roadmap](../README.md#следующие-шаги).

## Протокол

Отдельный сервис `7dbb0011-8e51-4f89-a9cb-9d40bb8c0e31`, RX `…0012…`, TX `…0013…`. Используется заголовок MB/v1, фрагменты ATT ≤20 байт и независимые sequence для команд. SELECT NDEF: AID `D2760000850101`; CC-файл `E103`, NDEF-файл `E104`. Поддерживаются SELECT и READ BINARY; запись запрещена.

Новый тип кадра 5 передаёт:

`01 | nameLen | uidHexLen | techLen | supported | name | uidHex | tech`.

Имя — 1…32 печатных ASCII-байта, UID — 0…20 hex-символов чётной длины, технология — 1…48 ASCII-байт, `supported` — 0/1. Ответ `TAG_OK` должен иметь тот же sequence; требуется также завершённая ATT-запись. Метаданные принимаются только при STOPPED. После переподключения запись передаётся заново. NFC стартует только для подтверждённого NDEF-снимка; каталог не меняется во время сеанса.

## Сборка

Из корня проекта:

```sh
python3 tags/android/build.py
python3 tags/android/build.py --test-only
```

Нужны JDK, Android SDK platform 36/build-tools 36.0.0 и Python 3. Используются общие `JAVA_HOME`, `ANDROID_SDK_ROOT` и локальный ключ `.local/signing/lab-debug.keystore`. Результат — `tags/android/build/tag-bridge-debug.apk`; сборка его не устанавливает.

JVM-набор содержит **170 проверок**: стандартные векторы файлов Type 4, границы APDU, сброс состояния, framing/metadata, порядок STATUS/ATT, независимый считыватель, доказательство BLE-обмена и порядок/отмена обновления GATT-кэша. APK запрашивает только NFC, BLUETOOTH_SCAN и BLUETOOTH_CONNECT; доступа к сети нет.
# Обновление 0.4.1: отметки синхронизации

Чекбокс под кнопкой «⋮» управляет включением метки в каталог браслета.
Нажатие карточки выбирает запись для NFC отдельно от чекбокса. При нажатии
«Синхронизировать с браслетом» каталог браслета заменяется только отмеченными
записями; снятые отметки не удаляют записи с Pixel. Пустой набор запрашивает
подтверждение перед очисткой непустого каталога браслета.

Отметки сохраняются в `syncToBand` каждой записи JSON. Старые записи без этого
поля считаются отмеченными, чтобы сохранить прежний состав синхронизации;
новые записи изначально не отмечены. Смена отметки увеличивает ревизию каталога
и сбрасывает старое разрешение на NFC. Во время передачи или NFC-сеанса
чекбоксы недоступны.

Дополнительно к JVM-набору проверка реального Android JSON/AtomicFile,
фильтрации передаваемых байтов и независимости выбора выполняется командой
`python3 tags/android/test_device.py --serial SERIAL` после сборки и установки
APK. Тест использует отдельный временный каталог в cache, не пользовательские
метки. Последний результат на Pixel 8a: **16 проверок PASS**.
