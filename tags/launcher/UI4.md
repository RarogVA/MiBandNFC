# UI4 — «Пульт», Roundabout RU NFC 4

Реализован один вариант с жирным начертанием и собран отдельный циферблат
**Roundabout RU NFC 4**, ID `999999990`, для релиза
[v1.0.0](../../docs/releases/v1.0.0.md). Целевая модель — `miwear.watch.p67glt`, прошивка **3.201.026**.
Аппаратно принятый UI3 и опубликованные файлы остаются неизменными.

## Экран

Экран 336×480, отступы от плоских краёв 5 px. У статуса верхние углы, а у
нижнего блока нижние углы повторяют скругление экрана. Радиус 56 px —
консервативная модель для проверки зазоров, а не измеренная спецификация панели.
Все видимые пиксели ресурсов проверены на попадание внутрь области с отступом.

| Элемент | Позиция | Размер |
| --- | --- | --- |
| Статус сервиса | 5, 5 | 326×49 |
| Карточка | 5, 87 | 326×216 |
| Нижний блок | 5, 336 | 326×139 |
| Предыдущая / следующая, внутри блока | 0, 0 / 163, 0 | 163×72 |
| Обновить, внутри блока | 0, 72 | 326×67 |

Это округление утверждённого макета до физических пикселей: высота статуса
48,96 → 49, высота «Обновить» 67,2 → 67. Пропорции карточки сохранены;
оба промежутка — от статуса до карточки и от карточки до нижнего блока —
равны **33 px**. Для этого карточка поднята на 23 px, размеры всех трёх блоков
сохранены. Нижние углы статуса имеют радиус 6.

На карточке тип метки находится сверху слева, контактная NFC-иллюстрация —
сверху справа. Бейдж типа увеличен по высоте с 28 до 32 px при ширине 114 px;
его центр и центр текста сохранены. Толщина линий NFC-иллюстрации увеличена с 2 до 3 px. Название расположено
справа от акцентной полоски; длинный текст ограничен собственным полем с
режимом многоточия. UID, заголовка страницы, индекса, нижней строки сообщений
и вертикальной прокрутки нет.

Название использует существующий **MiSans-Demibold 26 px**, тип —
**MiSans-Demibold 20 px**. Их инициализаторы и адреса проверяются по байтам
прошивки: [данные проверки](ui4-font-evidence.json). Общие стили прошивки не
изменяются и собственные шрифты в памяти браслета не создаются.
Статус (20 px) и «Обновить» (23 px) имеют жирное начертание в собственных
растровых ресурсах. Название и тип остаются динамическими native-метками.

## Действия

- Стрелки выбирают сохранённую запись через существующий API каталога. На
  границах списка соответствующая стрелка приглушена; переходы не зациклены.
  После выбора локальный результат проверяется максимум 20 секунд. Опрос
  прекращается сразу после отображения выбранной записи.
- **Обновить** перечитывает локальный каталог и состояние core. По уточнению
  пользователя это не запрос передачи каталога с Pixel. Синхронизация целого
  каталога по-прежнему запускается в Android-приложении.
- Кнопка статуса сохраняет одинаковые размеры во всех состояниях. Зелёный
  **Статус сервиса: OK** не содержит иконки. Красный **FAIL** содержит иконку
  обновления. Нажатие сразу показывает серое **Проверка**; четыре кадра иконки
  меняются только пока идёт проверка. Повторные нажатия в это время игнорируются.
- Если core отсутствует, выполняется прежняя защищённая попытка его загрузки.
  Успешный `insmod` сам по себе не даёт OK: необходим ответ зарегистрированного
  провайдера с живым циклом и без ошибки. Через максимум 20 секунд ожидание
  завершается FAIL. Текст подробной ошибки остаётся в диагностическом файле.
- Наличие живого или частично загруженного модуля запрещает повторный `insmod`.
  Ошибочный резидентный модуль может требовать перезагрузки; принудительной
  выгрузки нет. Проверка уже работающего модуля не перезагружает его.
- Таймеры страницы отменяются при pause, stop и destroy. При возврате выполняется
  разовое обновление. Постоянного опроса страницы и работы анимации в фоне нет.
  Остановка UI-таймеров не останавливает существующий NFC-сеанс core.

Core v1 и APK 0.4.1 не изменены. NFC запускается только явно на Pixel. Никакого
RF-пробуждения, новых платёжных функций или автоматического START не добавлено.

## Сборка без установки

```sh
build/shortcut-research-venv/bin/python tags/launcher/build_card.py
python3 tags/launcher/test_catalog_ui.py
build/shortcut-research-venv/bin/python tags/bootstrap/test.py
python3 tags/launcher/build_catalog_ui.py
build/shortcut-research-venv/bin/python tags/bootstrap/build_face.py \
  --core tags/catalog/build/catalog_core_v1.elf \
  --ui tags/launcher/build/nfc_tags_catalog_ui_v4.elf
build/shortcut-research-venv/bin/python tags/roundabout/level_labels.py
build/shortcut-research-venv/bin/python tags/roundabout/check_clearance.py
build/shortcut-research-venv/bin/python tags/bootstrap/verify_final.py
```

Результат: `build/roundabout-ru-nfc4-final.face`. Упаковщик автоматически включает
12 ресурсов UI4. Bootstrap требует успешного копирования всех ресурсов до
загрузки модулей; неполная копия показывает `UI ART` и не запускается.
Новый UI имеет собственные ELF, маркеры и путь `ui-catalog-v4.elf`. Переход с
резидентного UI1/UI2/UI3 требует перезагрузки. Первый тап по нижнему кругу после
перезагрузки загружает модуль и открывает страницу как в предыдущей версии.

Рендеры из тех же ресурсов: `build/catalog-ui4/screen-2x.png`,
`screen-fail-2x.png`, `screen-busy0-2x.png`. Это рендеры сборки, не фотографии
браслета; динамические MiSans-надписи приближённо показаны Arial Bold.
Материальные иконки стрелок/обновления сохраняют Apache-2.0 и исходные SVG;
формы карточки, кнопок и контактная иллюстрация созданы кодом проекта.

## Проверки и оставшаяся приёмка

- 922 native-проверки с AddressSanitizer и UndefinedBehaviorSanitizer: геометрия,
  границы списка, пустой каталог, сбои выделения памяти, достоверное состояние
  сервиса, тайм-аут, отказ повторной загрузки, завершение таймеров при уходе.
- 23 Lua-теста, в том числе отсутствие действий при открытии циферблата,
  готовность после загрузки, отказы копирования каждого из 12 ресурсов и
  совместимость маркеров предыдущих версий.
- 38 проверок байтов прошивки; ELF без неразрешённых символов и с сохранённой
  семантикой после удаления отладочной информации.
- Независимое чтение готового FACE: все встроенные файлы во всех четырёх обычных
  темах, отсутствие Lua в AOD, прежние границы круга, 490 исходных числовых
  ресурсов без изменений, прежние наклоны/координаты чисел и отступы подписей.
- Core и опубликованные FACE проверяются по прежним SHA-256.

Пользователь сообщил о выполненной проверке перед выпуском v1.0.0.
Автоматические отчёты выше описывают проверки на компьютере.
