# Roundabout: вход в «NFC-метки»

Исследовано на извлечённых с личного устройства исходниках **Roundabout 1.1.20**, пакет `120917397222`, P67, 336×480; прошивка **miwear.watch.p67glt 3.201.026**. Это статический разбор: ни системные адреса, ни настройки браслета этим исследованием не изменялись.

## Что подтверждено

Три круглые кнопки — редактируемые `Slot`, а не автоматический список установленных приложений. В `resources/manifest.xml` они имеют `SlotGroupName="1"`, `"2"`, `"3"`, расположение `(55,195)`, `(203,195)`, `(126,274)`. Каждый содержит **44 варианта: 43 элемента и пустой**. Геометрия редактора — 85×85, большинство отображаемых Widget — 84×84. Есть четыре оформления и связанные AOD-варианты: всего 24 таких Slot.

Действие отдельного Widget задаётся строкой, например `jumpApp="findPhone"`. Добавление приложения в launcher не пополняет эти перечисления. Для отдельного нового варианта нужны и регистрация приложения, и рабочая маршрутизация на него, и дополнительный элемент в каждом связанном Slot.

В точной прошивке найден общий eventbus-обработчик `jump_app` по `0x2c7c8c60` и таблица **39** имён по `0x2ca77d18` (file offset `0x9b7d18`). Цикл сравнивает строку с таблицей, затем допускает единственное специальное имя `wechat`. Остальные имена дают `app %s not found` и возврат. Это ограничение **этого обработчика**, а не всех кнопок циферблата. Последующий разбор подтвердил, что обычный compiled Widget использует другой обработчик `image_click_cb` по `0x2c7d0efc`, принимающий 8-битный native app ID напрямую; он использован в новом кандидате [Roundabout RU NFC](../roundabout/shortcut_README.md).

В таблице есть `nfcCard → 0x2b` и `recorder → 0x29`. Эти действия относятся к штатным приложениям; это **не** способ адресовать наш отдельный экран. Подмена штатного app ID для реализации нового пункта здесь не предлагается.

Ключевые участки дизассемблирования:

```text
0x2c7c8c7e  ldr r5, [pc, #0x7c]       ; table literal 0x2ca77d18
0x2c7c8c88  cmp r4, #0x27             ; ровно 39 записей
0x2c7c8c8c  ldr.w r1, [r5, r4, lsl #3]
0x2c7c8c92  bl 0x2c558468             ; строковое сравнение
0x2c7c8c9e  bne 0x2c7c8c88
0x2c7c8ca4  ldr.w r3, [r8, #4]       ; app ID найденной пары
0x2c7c8cb2  strh r3, [r7, #0xa]
0x2c7c8cb4  blx r2                    ; запуск
0x2c7c8cbe  mov r0, r6
0x2c7c8cc0  ldr r1, [pc, #0x40]      ; "wechat"
0x2c7c8cc2  bl 0x2c558468
0x2c7c8cc6  cbz r0, 0x2c7c8cde       ; отдельный WeChat path
0x2c7c8cce  ldr r1, [pc, #0x40]      ; "[%s] %s: app %s not found\n"
0x2c7c8cd2  bl 0x2c1beab8             ; лог, затем возврат
```

Механическая XML-правка `jumpApp="nfcTags"` или `jumpApp="0xC4"` сама по себе не подтверждает корректное кодирование. Статически проверенная схема — записать native ID в биты 4..11 compiled Widget (`u16@42`); loader переносит его в runtime bits 7..14, а `image_click_cb` передаёт штатному activity manager. В отдельной копии ID `999999994` нижний круг использует app ID `0xD4`. Исходная XML-таблица действий и ROM не изменяются. Полный разбор, кандидат и ограничения аппаратной проверки описаны в [shortcut_README.md](../roundabout/shortcut_README.md).

## Путь реализации

1. Зарегистрировать отдельное native-приложение «NFC-метки» с новым, предварительно проверенным свободным app ID. Пример автора [MiWatchNativeApps](https://github.com/m0tral/MiWatchNativeApps) поддерживает именно MB10 Pro GL 3.201.026. `install` регистрирует дескриптор и страницы, `app_launcher_add` добавляет пункт launcher. Наш Lua-экран циферблата сам по себе таким приложением не является.
2. Проверить открытие приложения из общего меню, возврат назад, состояние после смены циферблата, повторную регистрацию и перезагрузку. Не копировать из примера удаление текущего циферблата; модуль с живыми UI-callback должен оставаться загруженным. Регистрация, как в recorder, ожидаемо действует до перезагрузки; восстановление надо реализовать отдельно.
3. Найден и реализован штатный direct native-ID путь compiled Widget. Не нужны Lua/декларативный гибрид, runtime overlay, eventbus-подписка или расширение системного диспетчера. Требуется подтвердить на устройстве открытие зарегистрированного приложения.
4. Собрана отдельная копия `Roundabout RU NFC`: нижний круг фиксирован на «Метки» во всех темах/AOD, остальные два сохраняют прежние варианты. Расширять все три списка сейчас не требуется. Проверки бинарного файла и превью выполнены; нажатие/Back/перезагрузка проверяются отдельно на устройстве.

## Виджет слева

Это другой системный механизм, не Widget в XML циферблата. В [описании package manager](https://github.com/m0tral/MiWatchNativeApps/blob/master/common/miwear/app.h) есть `widgets_add(app, widgets, count)` и `widgets_remove(app)`. Но аргумент `widgets` остаётся `void *`: структура дескриптора и жизненный цикл виджета для этой прошивки пока не разобраны. Наличие метода не даёт безопасного шаблона для вызова.

В прошивке есть `normal_widget_sort`, `widget_sort_v001`, `/data/app/home/home.db`, `GET_SUPPORT_WIDGET_V3`, `GET_WIDGET_V3`, `SET_WIDGET_V3`. Это подтверждает отдельные реестр и порядок системных виджетов. Правка порядка не создаст отсутствующий тип виджета.

Следующий эксперимент: прочитать дескриптор одного простого штатного виджета, восстановить размер, поля ID, LVGL create/destroy/click callbacks и связь с app ID; затем зарегистрировать один временный виджет, нажатием открывающий уже проверенную страницу меток. После этого проверить выдачу в списке поддерживаемых виджетов Mi Fitness и сохранение порядка. До восстановления ABI `widgets_add` на браслете не вызывается.

## Повторить аудит

Исходный кеш лежит только в ignored `build/roundabout-source`; пользовательские данные аккаунта в отчёт не включены. Полная копия содержит PNG и исходный `resource.bin`; скрипт ничего не пересобирает.

```sh
python3 tags/ui-research/audit_roundabout.py build/roundabout-source \
  --firmware references/vela_ap.bin \
  --output tags/ui-research/roundabout-evidence.json
```

Скрипт проверяет идентичность исходника и SHA-256 прошивки, извлекает реальные Slot и карту действий. Файл `roundabout-evidence.json` содержит результат. Фиксированные адреса нельзя переносить на другую версию прошивки.
